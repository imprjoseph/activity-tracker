# 部署、營運與還原手冊

## 環境與首次部署

1. 分別建立 dev、staging、production 三個 Google Apps Script 專案，時區皆設為 `Asia/Taipei`。
2. 啟用進階 Google Drive API，使用各環境自己的 Script ID 與中央 Google Sheet；真實 ID 不提交版本庫。
3. 推送程式後在 Apps Script 編輯器執行 `setupTracker()`。既有資料庫會自動補上向後相容的新欄位，若欄位順序遭人工改動則會停止並要求先備份。
4. Web App 必須以「存取者身分」執行，且只開放公司網域。先由第一位管理員在後台新增使用者，再為各活動設定案件成員權限。
5. 上線前保持提醒的測試模式，設定測試信箱後完成 UAT；確認副知、寄送內容與配額後才切正式模式。

## 日常營運

- 每日提醒依管理後台設定執行；寄送鍵由類型、收件人、活動、日期與時段組成，同一時段成功後不會重寄。
- 暫時性寄送失敗最多嘗試三次，每次結果都寫入 `ReminderLog`；連續失敗或配額不足時由管理員查看寄送紀錄並處理帳號授權／配額。
- 每日約 02:00 建立主資料庫副本。預設保留 60 天，可用 Script Property `BACKUP_RETENTION_DAYS` 設為 30–90。
- 管理員可在後台按「立即建立備份」。匯入原檔另存於受限制的 Drive 資料夾，不放入 GitHub。
- 每次更新程式後重新執行 `setupTracker()`，以套用相容的資料欄位與重建提醒／備份觸發器。

## 還原程序

1. 暫停提醒規則，避免還原期間寄出舊資料提醒。
2. 在備份資料夾選定時間點副本，建立新的副本作為還原工作檔，原備份保持不動。
3. 核對 `Users`、`Events`、`Tasks`、`ImportBatches`、`ChangeLog` 與 `ReminderRules` 的筆數及抽樣內容。
4. 在 Script Properties 將 `TRACKER_SPREADSHEET_ID` 更新為還原工作檔 ID，再執行 `setupTracker()` 檢查結構並重建觸發器。
5. 以測試模式執行寄送前檢查，確認 Dashboard 與人工抽查一致後才重新啟用正式提醒。
6. 在變更紀錄或上線紀錄寫明還原時間點、原因、操作者、核准人與驗證結果。

## 上線閘門

- 公司網域、帳號人數、主管副知策略與 Gmail 配額已確認。
- 至少 5–10 份去識別化 Excel 樣本完成匯入測試。
- `npm test` 與語法檢查通過，UAT 關鍵缺陷歸零。
- 完成一次提醒測試與一次備份還原演練。
- production 部署與資料結構變更均有主管核准及可回復版本。
